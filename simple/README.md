# Простая версия проекта: ML отбирает алерты SIEM, LLM объясняет

Шесть шагов, каждый — один файл. Запускать из корня проекта (`D:\Default Project`) по порядку
или все сразу: `powershell -ExecutionPolicy Bypass -File simple\run_all.ps1`.

| Шаг | Файл | Что делает | Результат в `simple\results` |
|---|---|---|---|
| 1 | `1_data.py` | собирает алерты AIT-ADS, ставит метки по интервалам атак, делит каждую сеть на раннюю и позднюю часть, сети — на группы A и B | `alerts.parquet`, `labels_by_part.csv` |
| 2 | `2_samples.py` | две выборки по 200 алертов из поздней части | `sample1.csv`, `sample2.csv`, `share.csv` |
| 3 | `3_ml.py` | пять ML-моделей на одинаковых признаках, проверка на сетях, которых модель не видела; выбор итоговой; проверка признаков; обучение итоговой | `ml_comparison.csv`, `ablation.csv`, `by_scenario.csv`, `importance.csv`, `final_model.pkl` |
| 4 | `4_tandem.py` | итоговая модель отбирает алерты выборки 1, LLM объясняет отобранные (готовые объяснения берутся из старой версии) | `tandem\*.csv` |
| 5 | `5_eval.py` | итоговые таблицы: ML, LLM в одиночку, тандем, по сетям, признаки | `итог.xlsx`, `итог.json` |
| 6 | `6_dashboard.py` | дашборд одним файлом (оформление — `src\dashboard_template.html`) | `dashboard.html` |

Общие файлы в `simple\src`: `config.py` (все настройки), `features.py` (как алерт превращается в числа),
`metrics.py` (как считается качество), `llm.py` (промпт и вызов языковых моделей).

Признаки модели: текст алерта (даты скрыты), всплески одинаковых событий в сети, общая активность источника в сети,
источник (Wazuh или AMiner). Время суток, день недели, название сети и хост не используются.

Платные запросы к облачным LLM выполняются только явно: `python simple\4_tandem.py --ask "gpt-oss-120b"`
(нужна переменная окружения `POLZA_API_KEY`).

Готовые объяснения LLM старой версии (папка `results` проекта) используются шагом 4, если они есть; иначе объяснения запрашиваются заново.
